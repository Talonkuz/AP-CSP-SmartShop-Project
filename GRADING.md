# Project grading — 100 points

| Criterion | Full marks |
|---|---:|
| Data model and 10+ product catalog | 10 |
| Main menu and navigation | 5 |
| Display and search | 10 |
| Add/remove shopping cart | 15 |
| Totals, discounts and delivery | 15 |
| Rule-based product recommendations | 15 |
| Checkout, receipt and purchase history | 10 |
| Input validation / error handling | 5 |
| Testing report (15+ cases) | 5 |
| Code quality and individual explanation | 10 |
| **TOTAL** | **100** |

### Expectations

**Excellent (90–100):** All required features correct; robust edge-case handling; clean functions; accurate tests; student explains own algorithm and makes a change during defense.

**Good (75–89):** Main features work with small issues; adequate tests and explanation.

**Developing (60–74):** Partial features; repeated bugs or missed edge cases; some understanding.

**Needs revision (<60):** Important mandatory functionality missing or not demonstrated.

Up to **10 bonus points** may reward an optional extension, but final recorded result is capped at **100**. Bonus **does not replace** mandatory features.

Teacher scores the actual observed program, not code length or visual decoration.
